# API Vulnerability Scanner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the scanner-only Python package that discovers and normalizes vuln-bank APIs, manages isolated A/B sessions, executes the four approved scanner modules under strict safety policy, and emits verified-only scan results with redacted evidence references.

**Architecture:** A synchronous Python 3.11 package separates contracts, safety-aware HTTP, authentication, discovery, module rules, artifacts, and orchestration. `Scanner.discover()` retains secrets only in memory and returns a non-sensitive `DiscoveryResult`; `Scanner.execute()` validates LLM-produced references and delegates approved probes to an Executor that applies fixed rules immediately. Backend, LLM, database, frontend, and report implementations remain outside this branch.

**Tech Stack:** Python 3.11+, Pydantic 2, HTTPX, pytest, standard-library subprocess/JSON/hashlib/pathlib

## Global Constraints

- Work only on `feature/scanner`; do not implement backend, LLM, database, frontend, queue, or report features.
- Canonical scanner modules are exactly `bola`, `auth`, `transaction`, and `data_exposure`.
- Do not create `scanner/verifier.py` or an external `execution_evidence.json` contract.
- `normalized_api_graph.json` contains only operation ID, method, path template, inputs, and outputs.
- Actual credentials, tokens, cookies, object IDs, and raw response values must never appear in external JSON, logs, exceptions, or stored artifacts.
- Every outbound request, including redirects, must pass origin, path, method, module, budget, rate, and state-change checks.
- Transaction requests are denied unless the profile and plan approve the module and the state-change policy and HTTP method both permit the request.
- `scan_result.json` follows schema 1.2 and contains verified findings only.
- Tests must be local-only and use HTTPX MockTransport and fake Katana execution; never scan an external target.

`authorize()` is pure validation. `reserve_request()` applies the rate interval
