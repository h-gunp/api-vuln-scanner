# 프론트엔드

> 🔄 변경됨 (2026-07-26 재수정): JSON 계약은 수정하지 않는 정본으로 두고, 화면에서 사용하는 Module 목록·심각도 시점·AI 보고서 필드를 계약에 맞췄다.
> 

1차 MVP 핵심 기능은 다음과 같다.

| 기능 ID | 기능명 | 설명 |
| --- | --- | --- |
| FE-DASH-001 | 검사 URL 입력 | 사용자가 검사할 대상 서비스의 URL을 입력한다. 1차 목표에서는 vuln-bank URL을 기본값으로 제공한다. |
| FE-DASH-002 | 스캔 실행 | 🔄 변경됨: 백엔드 `POST /api/scans`에 `target_url`을 전송해 스캔을 시작한다. 실행 허용 모듈은 프론트에서 임의 선택하지 않고 백엔드가 생성한 `target_profile.json.approved_modules`의 `authz`, `input_validation`, `data_exposure`를 따른다. |
| FE-DASH-003 | 스캔 결과 요약 | 🔄 변경됨: `scan_status`, `report_status`, 검사 대상 URL, 발견 API 수와 Finding 수를 표시한다. 검사가 끝나도 보고서가 생성 중이면 두 상태를 구분해 보여준다. |
| FE-DASH-004 | API 상세 조회 | 발견 API 수를 클릭하면 검사한 API 목록과 상세정보를 표시한다. |
| FE-DASH-005 | Finding 현황 조회 | 전체 Finding 수와 취약점 유형별 개수를 표시한다. |
| FE-DASH-006 | Finding 상세 조회 | Finding 현황을 클릭하면 취약점 유형별 원형 그래프와 발견된 Finding 목록을 표시한다. |
| FE-DASH-007 | 취약점 유형 필터링 | Finding 상세 화면에서 특정 취약점 유형을 선택하면 해당 유형의 Finding만 표시한다. |
| FE-DASH-008 | Finding 세부사항 조회 | 🔄 변경됨: `scan_result.json` v1.2 기준으로 대상 API, `vulnerability_type`, 검증 규칙, 충족 조건, 영향 필드와 Evidence 참조를 표시한다. `severity`는 이 파일에 없으므로 `ai_report.json`이 준비된 뒤에만 추가 표시하며 원시 토큰·세션·객체 ID·Artifact 경로는 표시하지 않는다. |
| FE-DASH-009 | 상세 화면 검색 | 🔄 변경됨: API 및 Finding 상세 화면의 검색어를 백엔드 `query` 파라미터로 전달해 서버 측 검색 결과를 조회한다. |
| FE-DASH-010 | AI 리포트 조회 | 🔄 변경됨: AI 보고서가 준비되면 `ai_report.json` v1.2에 실제로 정의된 전체 위험도, 요약, 원인, 공격 흐름, 영향, 개선 권고와 `severity`를 표시한다. 현재 예시에 없는 규제 매핑 필드는 요구하지 않으며, Finding이 0건이어도 정상 결과로 표시한다. |
| FE-DASH-011 | 보고서 미리보기 | 🔄 변경됨: `report_status=READY`일 때만 최종 보고서를 미리 본다. `NOT_STARTED` 또는 `GENERATING`이면 버튼을 비활성화하고 생성 상태를 표시한다. |
| FE-DASH-012 | 보고서 다운로드 | 🔄 변경됨: `report_status=READY`이고 파일 생성이 완료된 경우에만 PDF 또는 JSON 보고서를 다운로드한다. |
| FE-DASH-013 | 🔄 변경됨: 사용자 자격증명 입력 | MVP 제외. 프론트엔드는 계정·비밀번호·토큰을 받거나 전송하지 않는다. `target_profile.json` v1.1의 `username_env`, `password_env` 참조는 백엔드·스캐너 런타임에서만 사용한다. |
