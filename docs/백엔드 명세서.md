# 1. 개요

## 1.1 목적

백엔드는 프론트엔드, 스캐너, LLM 사이에서 전체 보안 스캔 흐름을 관리한다.

프론트엔드는 검사할 URL을 입력하고 결과를 조회하며, 실제 크롤링·취약점 검사·증거 수집·Verifier 판정은 스캐너가 담당한다.

LLM은 다음 작업을 담당한다.

- API 관계 분석
- 검사 모듈 후보 선택
- 검사 계획 생성
- 검증된 Finding 설명
- 영향 분석
- 개선 권고 생성

백엔드는 다음 역할을 담당한다.

```
프론트 요청 수신
→ 스캔 작업 생성
→ target_profile.json 생성
→ Scanner Job 실행
→ JSON 산출물 수신 및 저장
→ LLM 작업 호출
→ 스캔 상태 관리
→ Finding / Evidence 저장
→ 프론트 조회 API 제공
→ AI Report 저장
→ 최종 보고서 생성 및 제공
```

# 3. 백엔드 구조

## 3.1 전체 구조

```
[Frontend]
    │
    │ REST API
    ▼
[FastAPI Backend]
    │
    ├── Scan Service
    │      ├── 스캔 생성
    │      ├── URL 검증
    │      ├── 상태 관리
    │      └── Target Profile 생성
    │
    ├── Scanner Orchestrator
    │      └── Scanner Job 실행
    │
    ├── LLM Orchestrator
    │      ├── Relationship Analyzer 호출
    │      ├── Planner 호출
    │      └── AI Report Generator 호출
    │
    ├── Result Service
    │      ├── Endpoint 저장
    │      ├── Finding 저장
    │      ├── Evidence 저장
    │      └── 통계 계산
    │
    ├── Report Service
    │      ├── AI Report 관리
    │      ├── HTML Report
    │      └── PDF Report
    │
    ▼
[PostgreSQL + Artifact Storage]
```

## 3.2 전체 데이터 흐름

```
1. 프론트에서 검사 URL 입력

2. POST /api/scans

3. 백엔드
   - URL 검증
   - scan_id 생성
   - vuln-bank 기본 Profile 적용
   - target_profile.json 생성

4. Scanner Job 실행

5. Scanner
   - user_a / user_b 로그인
   - OpenAPI + Katana 수집
   - API 정규화
   - 객체 ID 수집

6. normalized_api_graph.json 생성

7. 백엔드
   - Artifact 저장
   - Endpoint DB 저장

8. LLM Relationship Analyzer 실행

9. relationship_analysis.json 생성

10. 백엔드
    - 관계 분석 저장
    - Module Selection 저장

11. LLM Planner 실행

12. scan_plan.json 생성

13. Scanner
    - Policy Validation
    - Module 실행

14. execution_evidence.json 생성

15. Verifier 룰 기반 판정

16. scan_result.json 생성

17. 백엔드
    - Finding 저장
    - Evidence 연결
    - 스캔 완료 처리

18. LLM Analysis 실행

19. ai_report.json 생성

20. 백엔드
    - AI Analysis 저장
    - Report 생성

21. 프론트
    - Dashboard 조회
    - API 조회
    - Finding 조회
    - AI Report 조회
    - 보고서 미리보기 / 다운로드
```
